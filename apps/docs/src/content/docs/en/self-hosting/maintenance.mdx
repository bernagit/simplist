To keep the examples short, this alias holds the start command from [Deploy with Docker](/en/self-hosting/docker/):

```bash
alias simplist='docker compose --env-file docker/.env -f docker/docker-compose.yml -f docker/docker-compose.prod.yml -f docker/docker-compose.server.yml'
```

## Updating to a new version

What changes in each version is in the changelog. Users see it in the app too: it opens after an update, and is always in **Settings → Info**.

<Steps>

1. Make a [backup](#backups) of the database.

2. Update the deploy files, in case compose or nginx changed:

   ```bash
   git pull
   ```

3. Set the new version in `docker/.env`:

   ```ini
   VERSION=0.7.1
   ```

   Check the changelog for new variables a version needs, like the VAPID keys introduced in 0.7.0.

4. Pull the images and restart:

   ```bash
   simplist pull
   simplist up -d
   ```

   On startup the API applies database migrations by itself.

5. Check the logs:

   ```bash
   docker logs --tail 50 simplist-api
   ```

</Steps>

<Aside type="tip">
With `VERSION=latest` the same `pull` + `up -d` always takes you to the latest published version. It's convenient, but you may update without noticing: pinning the version is more predictable.
</Aside>

## Backups

There are three things to save:

| What | Where | Why |
|---|---|---|
| Database | `postgres_data` volume | Lists, tasks, users, settings |
| Session keys | `keys/` | Without them everyone has to sign in again |
| Configuration | `docker/.env` | Database password and VAPID keys |

For the database use `pg_dump`, which works while the instance is running:

```bash
docker exec simplist-db pg_dump -U postgres -d simplist -Fc > simplist-$(date +%F).dump
```

Replace `postgres` and `simplist` if you used other values for `POSTGRES_USER` and `POSTGRES_DB` in `docker/.env`. Keep the copies off the server, for example with a daily `cron` job that uploads them elsewhere.

## Restore

<Steps>

1. Stop the app and the API, keeping the database running:

   ```bash
   simplist stop nginx app api
   ```

2. Empty the database and restore the dump:

   ```bash
   docker exec simplist-db dropdb -U postgres simplist
   docker exec simplist-db createdb -U postgres simplist
   docker exec -i simplist-db pg_restore -U postgres -d simplist < simplist-2026-11-03.dump
   ```

3. Start everything again:

   ```bash
   simplist up -d
   ```

</Steps>

Restore `keys/` and `docker/.env` from the same backup too, so sessions and notifications keep working.

## Common problems

### The API doesn't start

Look for the reason in the logs:

```bash
docker logs simplist-api
```

- **`ENOENT … keys/private.key`**: the session keys are missing, or the `keys/` folder isn't next to `docker/`. See [Generate the session keys](/en/self-hosting/docker/#generate-the-session-keys).
- **SMTP connection error at startup**: the `SMTP_*` details are wrong, or still the example ones. Fix them, or delete the `SMTP_*` lines to run without email.
- **`password authentication failed`**: `POSTGRES_PASSWORD` changed after the first start. Put the original one back, or change it inside PostgreSQL too.

### I can't sign in, or I'm signed out right away

Session cookies only work over HTTPS. Make sure the instance is opened with `https://` and that the reverse proxy forwards the `X-Forwarded-Proto` header. Only for an instance served over HTTP on a local network, set `COOKIE_SECURE=false`.

### The first user's registration link points to localhost

`APP_URL` is missing from `docker/.env`. Set it and restart the API: as long as there are no users, a new invite with the right address is created on startup.

### Notifications don't arrive

- The API logs must show `Task reminders started.`. If they show `Push notifications are disabled` instead, the VAPID keys are missing.
- In **Settings → Notifications** the device must be on, and the test notification must arrive.
- The reminder has to be turned on for each task (bell icon).
- On iPhone and iPad notifications only work in the app added to the Home Screen.

### The documentation doesn't open on `docs.`

The subdomain must point to the server, and the reverse proxy must forward it keeping the `Host` header. Without that header nginx can't tell it's the subdomain and shows the app.
