title: Deploy with Docker
description: Install Simplist on your server with Docker Compose, step by step.
---

import { Aside, Steps, Tabs, TabItem } from '@astrojs/starlight/components';

This guide takes you from an empty server to a Simplist instance reachable over HTTPS. It takes about 15 minutes.

In the examples the instance answers at `https://simplist.example.com`: replace it with your domain.

<Steps>

1. ## Get the deploy files

   On the server you need the repository's `docker/` folder (compose files, nginx configuration, example `.env`) and a `keys/` folder next to it. The easiest way is to clone the repository:

   ```bash
   git clone --depth 1 https://github.com/bernagit/simplist.git
   cd simplist
   ```

   All the following commands run from this folder.

2. ## Generate the session keys

   The API signs sessions with an **EC P-384** key pair (ES384), read from `keys/private.key` and `keys/public.pem`. Generate it once:

   <Tabs>
   <TabItem label="With Docker">

   ```bash
   mkdir -p keys
   docker run --rm -v "$PWD/keys:/keys" alpine/openssl \
     ecparam -name secp384r1 -genkey -noout -out /keys/private.key
   docker run --rm -v "$PWD/keys:/keys" alpine/openssl \
     ec -in /keys/private.key -pubout -out /keys/public.pem
   ```

   </TabItem>
   <TabItem label="With openssl">

   ```bash
   mkdir -p keys
   openssl ecparam -name secp384r1 -genkey -noout -out keys/private.key
   openssl ec -in keys/private.key -pubout -out keys/public.pem
   ```

   </TabItem>
   </Tabs>

   <Aside type="caution">
   Keep `keys/private.key` with your backups and don't share it. If you change it, everyone has to sign in again.
   </Aside>

3. ## Create the configuration file

   ```bash
   cp docker/.env.example docker/.env
   ```

   Open `docker/.env` and set at least these values:

   ```ini
   # Version to install: pin it (for example 0.7.1) instead of "latest",
   # so you update when you decide to
   VERSION=0.7.1

   # Public address of the instance: used in email links and in the first user link
   APP_URL=https://simplist.example.com
   CORS_ORIGIN=https://simplist.example.com

   # Database password: pick a long random one
   POSTGRES_PASSWORD=a-long-random-password
   ```

   <Aside type="caution" title="Email">
   When all the `SMTP_*` variables are set, the API checks the mail server at startup and **does not start** if the check fails. The example values don't work:
   - put in your SMTP server's details;
   - or, if you don't need email, delete or comment out the `SMTP_*` and `MAIL_FROM_*` lines.

   Without email Simplist works normally. You only lose the welcome email, email invites and password reset; invites can still be shared as a link.
   </Aside>

   All other options are described in [Configuration](/en/self-hosting/configuration/).

4. ## Turn on push notifications (recommended)

   Task reminders use push notifications, which need a **VAPID** key pair. Generate it once:

   ```bash
   docker run --rm node:24-alpine npx -y web-push@3.6.7 generate-vapid-keys
   ```

   and copy the two values into `docker/.env`:

   ```ini
   VAPID_PUBLIC_KEY=BNc...
   VAPID_PRIVATE_KEY=x7f...
   ```

   <Aside>
   Without these keys Simplist still works, but reminders are off. Keep them: if you change them, every device has to turn notifications on again.
   </Aside>

5. ## Don't expose the database

   `docker/docker-compose.yml` publishes PostgreSQL on port `5432` of the server, which is handy in development. In production, close it by creating `docker/docker-compose.server.yml`:

   ```yaml title="docker/docker-compose.server.yml"
   services:
     db:
       ports: !reset []
   ```

   (`!reset` needs Docker Compose 2.24 or later.)

6. ## Start Simplist

   ```bash
   docker compose --env-file docker/.env \
     -f docker/docker-compose.yml \
     -f docker/docker-compose.prod.yml \
     -f docker/docker-compose.server.yml \
     up -d
   ```

   On the first start the API creates the database tables. Check that everything is up:

   ```bash
   docker compose --env-file docker/.env -f docker/docker-compose.yml -f docker/docker-compose.prod.yml ps
   curl http://localhost:3000/api/health
   ```

   The answer must be `{"status":"ok"}`.

7. ## Create the first user

   Registration on Simplist is by invitation only. When the database is empty, the API creates an invite for the first user and prints the link in its logs:

   ```bash
   docker logs simplist-api 2>&1 | grep "Register at"
   ```

   ```text
   Register at: https://simplist.example.com/register?token=...
   ```

   Open the link and create your account. You invite everyone else from the app, in **Settings → Invites**.

   <Aside type="tip">
   The link is valid for one hour. If it expires before you use it, restart the API with `docker restart simplist-api`: as long as there are no users, every start creates a new invite.
   </Aside>

8. ## Serve it over HTTPS

   The nginx container answers over HTTP on port `3000`. In front of it you need a reverse proxy that handles the certificate and forwards requests **keeping the `Host` header**. That header also tells nginx when a request is for the `docs.` subdomain.

   <Tabs>
   <TabItem label="Caddy">

   Caddy gets and renews the certificate on its own:

   ```text title="/etc/caddy/Caddyfile"
   simplist.example.com, docs.simplist.example.com {
     reverse_proxy localhost:3000
   }
   ```

   </TabItem>
   <TabItem label="nginx">

   ```nginx title="/etc/nginx/sites-available/simplist"
   server {
     listen 443 ssl http2;
     server_name simplist.example.com docs.simplist.example.com;

     ssl_certificate     /etc/letsencrypt/live/simplist.example.com/fullchain.pem;
     ssl_certificate_key /etc/letsencrypt/live/simplist.example.com/privkey.pem;

     client_max_body_size 5m;

     location / {
       proxy_pass http://127.0.0.1:3000;
       proxy_set_header Host $host;
       proxy_set_header X-Real-IP $remote_addr;
       proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
       proxy_set_header X-Forwarded-Proto $scheme;
     }
   }
   ```

   </TabItem>
   </Tabs>

   The `docs.` subdomain is optional: if you don't want the documentation on your instance, don't create its DNS record.

</Steps>

## Final check

- Open `https://simplist.example.com` and sign in.
- The API logs (`docker logs simplist-api`) must show `Application ready` and, if you set the VAPID keys, `Task reminders started.`.
- On a phone, install the app and turn notifications on in **Settings → Notifications**, then send a test notification.

<Aside type="note" title="Without HTTPS">
On a local network without HTTPS you can set `COOKIE_SECURE=false` in `docker/.env` to be able to sign in. Installing the app and push notifications still need HTTPS, except on `localhost`.
</Aside>
