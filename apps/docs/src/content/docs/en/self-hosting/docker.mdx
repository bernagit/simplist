This guide takes you from an empty server to a Simplist instance reachable over HTTPS. It takes about 10 minutes, and you don't need to clone the repository: two files are enough.

In the examples the instance answers at `https://simplist.example.com`: replace it with your domain.

<Steps>

1. ## Download the files

   Create a folder for the instance and download the Compose file and the example configuration:

   ```bash
   mkdir simplist && cd simplist
   curl -fsSLO https://raw.githubusercontent.com/bernagit/simplist/master/docker/compose.yaml
   curl -fsSL https://raw.githubusercontent.com/bernagit/simplist/master/docker/.env.example -o .env
   ```

   All the following commands run from this folder. Docker Compose reads `compose.yaml` and `.env` from here, with no other options.

2. ## Configure the instance

   Open `.env` and set at least these values:

   ```ini
   # Version to install: pin it (for example 0.7.4) instead of "latest",
   # so you update when you decide to
   VERSION=0.7.4

   # Public address of the instance: used in email links and in the first user link
   APP_URL=https://simplist.example.com
   CORS_ORIGIN=https://simplist.example.com

   # Database password: pick a long random one before the first start
   POSTGRES_PASSWORD=a-long-random-password
   ```

   <Aside title="Email (optional)">
   For the welcome email, email invites and password reset, uncomment the `SMTP_*` and `MAIL_FROM_*` lines and put in your mail server's details. If the server doesn't answer at startup, the API says so in the logs and starts anyway.

   Without email Simplist works normally: invites are shared as a link.
   </Aside>

   To also serve this documentation on your instance, at `/docs/`, add `COMPOSE_PROFILES=docs`. All other options are described in [Configuration](/docs/en/self-hosting/configuration/).

3. ## Start Simplist

   ```bash
   docker compose up -d
   ```

   On the first start the API creates the database tables and generates its secrets in the `keys/` folder:

   - `private.key` and `public.pem`, the keys that sign sessions;
   - `vapid.json`, the push notification keys.

   <Aside type="caution">
   Keep the `keys/` folder with your backups and don't share it. If you lose it, everyone has to sign in again and turn notifications back on on every device.
   </Aside>

   Check that everything is up:

   ```bash
   docker compose ps
   curl http://localhost:3000/api/health
   ```

   The answer must contain `"status":"ok"` and the installed version. The database isn't reachable from outside: the only published service is the proxy, on port `3000`.

4. ## Create the first user

   Registration on Simplist is by invitation only. When the database is empty, the API creates an invite for the first user and prints the link in its logs:

   ```bash
   docker compose logs api | grep "Register at"
   ```

   ```text
   Register at: https://simplist.example.com/register?token=...
   ```

   Open the link and create your account. You invite the next users from the app, in **Settings → Invites**.

   <Aside type="tip">
   The link is valid for one hour. If it expires before you use it, restart the API with `docker compose restart api`: as long as there are no users, every start creates a new invite.
   </Aside>

5. ## Serve it over HTTPS

   Simplist's proxy answers over HTTP on port `3000`. In front of it you need a reverse proxy that handles the certificate and forwards requests **keeping the `Host` header**.

   <Tabs>
   <TabItem label="Caddy">

   Caddy gets and renews the certificate by itself:

   ```text title="/etc/caddy/Caddyfile"
   simplist.example.com {
     reverse_proxy localhost:3000
   }
   ```

   </TabItem>
   <TabItem label="nginx">

   ```nginx title="/etc/nginx/sites-available/simplist"
   server {
     listen 443 ssl http2;
     server_name simplist.example.com;

     ssl_certificate     /etc/letsencrypt/live/simplist.example.com/fullchain.pem;
     ssl_certificate_key /etc/letsencrypt/live/simplist.example.com/privkey.pem;

     client_max_body_size 5m;

     location / {
       proxy_pass http://127.0.0.1:3000;
       proxy_set_header Host $host;
       proxy_set_header X-Real-IP $remote_addr;
       proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
       proxy_set_header X-Forwarded-Proto $scheme;
     }
   }
   ```

   </TabItem>
   </Tabs>

   If port `3000` is already taken on the server, pick another one with `HTTP_PORT` in `.env`.

</Steps>

## Final check

- Open `https://simplist.example.com` and sign in.
- The API logs (`docker compose logs api`) must show `Application ready` and `Task reminders started.`.
- From a phone, install the app and turn on notifications in **Settings → Notifications**, then send a test notification.

<Aside type="note" title="Without HTTPS">
On a local network without HTTPS you can set `COOKIE_SECURE=false` in `.env` to be able to sign in. Installing the app and push notifications still need HTTPS, except on `localhost`.
</Aside>
