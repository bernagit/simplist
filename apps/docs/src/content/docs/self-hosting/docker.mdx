Questa guida porta da un server vuoto a un'istanza di Simplist raggiungibile in HTTPS. Servono circa 10 minuti, e non serve clonare il repository: bastano due file.

Negli esempi l'istanza risponde su `https://simplist.esempio.it`: sostituiscilo con il tuo dominio.

<Steps>

1. ## Scarica i file

   Crea una cartella per l'istanza e scarica il file di Compose e la configurazione di esempio:

   ```bash
   mkdir simplist && cd simplist
   curl -fsSLO https://raw.githubusercontent.com/bernagit/simplist/master/docker/compose.yaml
   curl -fsSL https://raw.githubusercontent.com/bernagit/simplist/master/docker/.env.example -o .env
   ```

   Tutti i comandi seguenti partono da questa cartella. Docker Compose legge `compose.yaml` e `.env` da qui, senza altre opzioni.

2. ## Configura l'istanza

   Apri `.env` e imposta almeno questi valori:

   ```ini
   # Versione da installare: fissala (per esempio 0.7.4) invece di "latest",
   # così aggiorni quando lo decidi tu
   VERSION=0.7.4

   # Indirizzo pubblico dell'istanza: usato nei link delle email e nel link del primo utente
   APP_URL=https://simplist.esempio.it
   CORS_ORIGIN=https://simplist.esempio.it

   # Password del database: scegline una lunga e casuale prima del primo avvio
   POSTGRES_PASSWORD=una-password-lunga-e-casuale
   ```

   <Aside title="Email (facoltativa)">
   Per l'email di benvenuto, gli inviti via email e il recupero della password, togli il commento alle righe `SMTP_*` e `MAIL_FROM_*` e inserisci i dati del tuo server di posta. Se all'avvio il server non risponde, l'API lo segnala nei log e parte comunque.

   Senza email Simplist funziona normalmente: gli inviti si condividono con un link.
   </Aside>

   Per avere anche questa documentazione sulla tua istanza, all'indirizzo `/docs/`, aggiungi `COMPOSE_PROFILES=docs`. Tutte le altre opzioni sono descritte in [Configurazione](/docs/self-hosting/configuration/).

3. ## Avvia Simplist

   ```bash
   docker compose up -d
   ```

   Al primo avvio l'API crea le tabelle del database e genera i suoi segreti nella cartella `keys/`:

   - `private.key` e `public.pem`, le chiavi che firmano le sessioni;
   - `vapid.json`, le chiavi delle notifiche push.

   <Aside type="caution">
   Conserva la cartella `keys/` insieme ai backup e non condividerla. Se la perdi, tutti gli utenti devono rifare l'accesso e riattivare le notifiche su ogni dispositivo.
   </Aside>

   Controlla che sia tutto a posto:

   ```bash
   docker compose ps
   curl http://localhost:3000/api/health
   ```

   La risposta deve contenere `"status":"ok"` e la versione installata. Il database non è raggiungibile dall'esterno: l'unico servizio pubblicato è il proxy, sulla porta `3000`.

4. ## Crea il primo utente

   La registrazione su Simplist avviene solo su invito. Quando il database è vuoto, l'API crea un invito per il primo utente e stampa il link nei log:

   ```bash
   docker compose logs api | grep "Register at"
   ```

   ```text
   Register at: https://simplist.esempio.it/register?token=...
   ```

   Apri il link e crea il tuo account. Gli utenti successivi li inviti dall'app, in **Impostazioni → Inviti**.

   <Aside type="tip">
   Il link vale un'ora. Se scade prima che tu lo usi, riavvia l'API con `docker compose restart api`: finché non esiste nessun utente, a ogni avvio viene creato un nuovo invito.
   </Aside>

5. ## Pubblica in HTTPS

   Il proxy di Simplist risponde in HTTP sulla porta `3000`. Davanti serve un reverse proxy che gestisca il certificato e inoltri le richieste **mantenendo l'header `Host`**.

   <Tabs>
   <TabItem label="Caddy">

   Caddy ottiene e rinnova il certificato da solo:

   ```text title="/etc/caddy/Caddyfile"
   simplist.esempio.it {
     reverse_proxy localhost:3000
   }
   ```

   </TabItem>
   <TabItem label="nginx">

   ```nginx title="/etc/nginx/sites-available/simplist"
   server {
     listen 443 ssl http2;
     server_name simplist.esempio.it;

     ssl_certificate     /etc/letsencrypt/live/simplist.esempio.it/fullchain.pem;
     ssl_certificate_key /etc/letsencrypt/live/simplist.esempio.it/privkey.pem;

     client_max_body_size 5m;

     location / {
       proxy_pass http://127.0.0.1:3000;
       proxy_set_header Host $host;
       proxy_set_header X-Real-IP $remote_addr;
       proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
       proxy_set_header X-Forwarded-Proto $scheme;
     }
   }
   ```

   </TabItem>
   </Tabs>

   Se sul server la porta `3000` è già occupata, scegline un'altra con `HTTP_PORT` in `.env`.

</Steps>

## Verifica finale

- Apri `https://simplist.esempio.it` e accedi.
- Nei log dell'API (`docker compose logs api`) devono comparire `Application ready` e `Task reminders started.`.
- Da un telefono, installa l'app e attiva le notifiche in **Impostazioni → Notifiche**, poi invia una notifica di prova.

<Aside type="note" title="Senza HTTPS">
Su una rete locale senza HTTPS puoi impostare `COOKIE_SECURE=false` in `.env` per poter accedere. Installazione come app e notifiche push però richiedono HTTPS, tranne che su `localhost`.
</Aside>
