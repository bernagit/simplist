Per comodità, negli esempi questo alias raccoglie il comando di avvio usato in [Deploy con Docker](/self-hosting/docker/):

```bash
alias simplist='docker compose --env-file docker/.env -f docker/docker-compose.yml -f docker/docker-compose.prod.yml -f docker/docker-compose.server.yml'
```

## Aggiornare a una nuova versione

Le novità di ogni versione sono nel changelog: gli utenti lo vedono anche nell'app, che lo mostra dopo un aggiornamento ed è sempre in **Impostazioni → Info**.

<Steps>

1. Fai un [backup](#backup) del database.

2. Aggiorna i file di deploy, nel caso siano cambiati compose o nginx:

   ```bash
   git pull
   ```

3. Imposta la nuova versione in `docker/.env`:

   ```ini
   VERSION=0.7.1
   ```

   Controlla nel changelog se la versione richiede nuove variabili, per esempio le chiavi VAPID introdotte nella 0.7.0.

4. Scarica le immagini e riavvia:

   ```bash
   simplist pull
   simplist up -d
   ```

   All'avvio l'API applica da sola le migrazioni del database.

5. Controlla i log:

   ```bash
   docker logs --tail 50 simplist-api
   ```

</Steps>

<Aside type="tip">
Con `VERSION=latest` lo stesso `pull` + `up -d` porta sempre all'ultima versione pubblicata. È comodo, ma rischi di aggiornare senza accorgertene: fissare la versione è più prevedibile.
</Aside>

## Backup

I dati da salvare sono tre:

| Cosa | Dove | Perché |
|---|---|---|
| Database | volume `postgres_data` | Liste, attività, utenti, impostazioni |
| Chiavi di sessione | `keys/` | Senza, tutti gli utenti devono rifare l'accesso |
| Configurazione | `docker/.env` | Password del database e chiavi VAPID |

Per il database usa `pg_dump`, che funziona anche con l'istanza accesa:

```bash
docker exec simplist-db pg_dump -U postgres -d simplist -Fc > simplist-$(date +%F).dump
```

Sostituisci `postgres` e `simplist` se in `docker/.env` hai usato valori diversi per `POSTGRES_USER` e `POSTGRES_DB`. Conserva le copie fuori dal server, per esempio con un `cron` giornaliero che le carica altrove.

## Ripristino

<Steps>

1. Ferma app e API, lasciando acceso il database:

   ```bash
   simplist stop nginx app api
   ```

2. Svuota il database e ripristina il dump:

   ```bash
   docker exec simplist-db dropdb -U postgres simplist
   docker exec simplist-db createdb -U postgres simplist
   docker exec -i simplist-db pg_restore -U postgres -d simplist < simplist-2026-11-03.dump
   ```

3. Riavvia tutto:

   ```bash
   simplist up -d
   ```

</Steps>

Ripristina anche `keys/` e `docker/.env` dallo stesso backup, così le sessioni e le notifiche continuano a funzionare.

## Problemi comuni

### L'API non parte

Guarda il motivo nei log:

```bash
docker logs simplist-api
```

- **`ENOENT … keys/private.key`**: mancano le chiavi di sessione, oppure la cartella `keys/` non è accanto a `docker/`. Vedi [Genera le chiavi di sessione](/self-hosting/docker/#genera-le-chiavi-di-sessione).
- **Errore di connessione SMTP all'avvio**: i dati `SMTP_*` sono sbagliati, o sono rimasti quelli di esempio. Correggili, oppure cancella le righe `SMTP_*` per fare a meno dell'email.
- **`password authentication failed`**: `POSTGRES_PASSWORD` è cambiata dopo il primo avvio. Rimetti quella originale, oppure cambiala anche dentro PostgreSQL.

### Non riesco ad accedere, o vengo disconnesso subito

I cookie di sessione funzionano solo in HTTPS. Controlla che l'istanza sia aperta con `https://`, e che il reverse proxy inoltri l'header `X-Forwarded-Proto`. Solo per un'istanza in HTTP su rete locale, imposta `COOKIE_SECURE=false`.

### Il link di registrazione del primo utente punta a localhost

Manca `APP_URL` in `docker/.env`. Impostala e riavvia l'API: finché non esiste nessun utente, all'avvio viene creato un nuovo invito con l'indirizzo giusto.

### Le notifiche non arrivano

- Nei log dell'API deve comparire `Task reminders started.`. Se invece compare `Push notifications are disabled`, mancano le chiavi VAPID.
- In **Impostazioni → Notifiche** il dispositivo deve risultare attivo, e la notifica di prova deve arrivare.
- Il promemoria va attivato su ogni attività (icona della campanella).
- Su iPhone e iPad le notifiche funzionano solo nell'app aggiunta alla schermata Home.

### La documentazione non si apre su `docs.`

Il sottodominio deve puntare al server, e il reverse proxy deve inoltrarlo mantenendo l'header `Host`. Senza quell'header nginx non riconosce il sottodominio e mostra l'app.
